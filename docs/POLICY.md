# Stage 2 模拟政策与状态流程

所有规则是本项目的演示商家规则，不表示真实平台政策或法律意见。默认版本 `demo-v1:r7:q30:h1000.00`。

## 决策顺序

1. 缺订单 → NEED_MORE_INFO；未支付、已取消、无实付 → DENY。
2. 签收未收到/运输未收到，或已发货想取消 → 查询有效物流并转 CREATE_LOGISTICS_TICKET，不自动退款。
3. 未发货取消 → 必须为 PAID，且不存在已占用退款/换货；整单退实付。
4. 商品售后 → 已签收/已完成、明确商品数量、时间有效、无整单退款冲突。
5. 无理由 → 7×24 小时内（边界包含），可退且非 final_sale，仅 RETURN_AND_REFUND。
6. 破损/错发 → 30×24 小时内、提供证据，支持退货退款或换货；必须人工审批。
7. 少件 → 30×24 小时内、提供证据，支持 REFUND_MISSING_ITEM 或换货；必须人工审批，少件退款不要求退回不存在的商品。
8. 根据历史成功/在途/预留记录，计算订单金额和商品数量剩余。
9. 拟退款金额或换货价值 ≥1000.00 元 → HIGH 风险与人工审批；有质量证据待核验但金额较低 → MEDIUM；其余 LOW。

final_sale/refundable 的限制用于本项目的无理由退货，不用于自动否决质量问题；质量问题仍走证据核验。

## 四种政策决策

| decision | 后续 |
|---|---|
| ALLOW | 保存预留；普通动作 READY，退货退款 WAITING_RETURN |
| REQUIRE_APPROVAL | 保存预留和 Approval；WAITING_APPROVAL |
| NEED_MORE_INFO | BLOCKED；工单 WAITING_CUSTOMER，补资料后使用新幂等键 |
| DENY | BLOCKED；不创建新退款预留；工单 IN_PROGRESS 以便继续处理 |

预览接口只读，没有预留，也不保证后续提交仍得到相同结果。提交、审批、收货、执行都以当时数据库状态重新判断。

## 人工审批

批准仅解除人工审批等待，不直接退款。RETURN_AND_REFUND 批准后等待管理员模拟仓库收货；其他动作进入 READY。

拒绝使申请 REJECTED，退款 REJECTED，工单 RESOLVED，额度和数量释放。需要再次申请可创建新工单，使用新幂等键。同一审批重复提交相同结果返回原审批，改变结果返回 409；原审核人和原理由保持不变。

审批通过前若订单已发货、额度变化或政策版本变化，原授权作废，审批自动拒绝并留下原因，不能用“人工批准”绕过硬规则。

## 退货、模拟执行与重试

- 收货只允许 WAITING_RETURN；重复收货确认不会累加数量或增加事件。
- 模拟执行只允许 READY 或可重试 FAILED，并再次检查审批和政策。
- 退款状态：PENDING → APPROVED → PROCESSING → SUCCESS / FAILED；失败可重试为 PROCESSING，再成功。
- FAILED 保留资金/数量预留，以同一个申请 ID 重试；重复提交 FAILURE 返回原状态。当前没有超时释放和撤回 API。
- 成功后，执行状态 SUCCESS 且设置 final_action。整单取消还会把订单变为 CANCELLED。
- 换货 SUCCESS 表示模拟“已安排换货发出”，没有创建真实库存单或第二个包裹。
- 物流动作 SUCCESS 表示调查任务已建立在当前工单，工单仍 IN_PROGRESS；调查结果由管理员后续处理工单状态。
- 审批/收货/执行重新计算发现授权失效：申请 BLOCKED、退款 REJECTED 释放预留，工单回 IN_PROGRESS；原始快照与所有事件保留。

## 明确限制

不支持运费/税费、赠品价值、支付拆单、跨币种、优惠券退回、多包裹、退货质检拒收、补寄真实库存、真实支付幂等协议、政策回溯迁移或自动风险学习。

证据是布尔存在标记 + 人工备注，没有图片上传与附件留存。期限在申请时锁定；没有单独限制用户寄回退货的期限。质量申请过期后规则拒绝，但工单仍可人工继续沟通，不宣称消灭真实消费者权利。

这些功能留待明确业务需求后开发，不以不真实的成功状态掩盖缺失能力。
